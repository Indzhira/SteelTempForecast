# Steel Temperature Forecast

Учебный проект Data Science: прогнозирование финальной температуры стали по данным технологического процесса.

## Результат

Для решения задачи были сравнены несколько подходов к регрессии:

- DummyRegressor - baseline;
- Random Forest;
- LightGBM;
- XGBoost;
- полносвязная нейронная сеть на PyTorch.

Основные модели сравнивались по `MAE` на 5-кратной кросс-валидации.

| Model | Схема оценки | MAE, °C |
|---|---|---:|
| DummyRegressor | 5-fold CV | 7.99 |
| RandomForest | 5-fold CV | 6.58 |
| LightGBM | 5-fold CV | 6.50 |
| **XGBoost** | **5-fold CV** | **6.47** |
| NeuralNet | отдельная validation-выборка | 6.85 |

По результатам кросс-валидации для финального тестирования был выбран **XGBoost**.

На отложенной тестовой выборке:

- **MAE = 6.69°C**
- **R² = 0.37**
- DummyRegressor: **MAE = 8.28°C**

Таким образом, XGBoost снизил MAE относительно константного baseline на **1.59°C** и выполнил установленное в задаче требование: **MAE < 6.8°C**

## Постановка задачи

Необходимо предсказать последнюю валидную измеренную температуру стали для партии по данным технологического процесса.

Целевая переменная: `last_temp`

В проекте предполагается, что прогноз формируется после учтённых технологических операций, но **до финального измерения температуры**.

Это ограничение учитывается при формировании признаков: в модель не включается информация, которая становится известна только в момент получения целевой переменной.

---

## Данные

Исходные данные представлены несколькими таблицами и содержат информацию о:

- нагреве электродами;
- подаче сыпучих материалов;
- времени подачи сыпучих материалов;
- подаче проволочных материалов;
- времени подачи проволочных материалов;
- продувке газом;
- измерениях температуры.

Всего использовано **7 исходных таблиц**.

Данные агрегируются до уровня одной партии стали (`key`).

Исходный датасет в репозиторий не включён. Ноутбук содержит код обработки данных, сохранённые результаты вычислений и визуализации.

## Подготовка данных

В ходе подготовки данных:

- приведены к единому формату названия признаков и типы данных;
- исследованы пропуски и дубликаты;
- исключены некорректные измерения температуры;
- проверены аномальные значения;
- технологические данные агрегированы на уровне партии;
- проверена временная последовательность операций;
- удалены константные признаки.

Статистически необычные значения не удалялись автоматически только на основании IQR или boxplot: наблюдения сохранялись, если не было оснований считать их ошибочными.

Отдельно проверено, что использованные операции нагрева и подачи материалов происходят не позже финального измерения температуры.

## Feature engineering

Сформированы признаки, характеризующие технологический процесс.

### Нагрев

- количество циклов нагрева;
- суммарное время нагрева;
- средняя полная мощность;
- характеристики соотношения активной и реактивной мощности;
- величина, пропорциональная суммарной активной энергии.

### Материалы

Для сыпучих и проволочных материалов сохранены:

- суммарное количество материалов;
- временные интервалы их подачи.

### Другие признаки

- объём использованного газа;
- начальная температура партии.

Идентификатор партии `key` используется только для объединения таблиц и не передаётся модели в качестве признака.

## Контроль data leakage

Особое внимание уделено доступности признаков в предполагаемый момент формирования прогноза.

Например, признак `measurement_interval` (`last_time` - `first_time`) не используется при обучении модели, поскольку зависит от времени последнего измерения температуры. В реальном сценарии эта информация становится известна одновременно с целевой переменной.

Также перед моделированием проверено, что агрегированные операции нагрева и подачи материалов не происходят после финального измерения температуры.

---

## Валидация

Данные разделены на:

- обучающую выборку;
- отложенную тестовую выборку.

Тестовая выборка не использовалась при подборе гиперпараметров и выборе основной модели.

Для Random Forest, LightGBM и XGBoost параметры подбирались с помощью `RandomizedSearchCV` и 5-кратной кросс-валидации по метрике: `neg_mean_absolute_error`

В качестве baseline использован: `DummyRegressor(strategy='median')`

Нейронная сеть оценивалась на отдельной validation-выборке, поэтому её MAE не используется для прямого ранжирования вместе со средним CV MAE остальных моделей.

## Интерпретация модели

Для анализа вклада признаков в прогноз XGBoost использованы **SHAP values**.

Среди наиболее важных признаков оказались:

- суммарное время нагрева электродами (`heat_time`);
- начальная температура (`first_temp`).

Дополнительный анализ показывает положительную статистическую связь этих признаков с финальной температурой.

SHAP используется здесь для интерпретации поведения модели и **не рассматривается как доказательство причинного влияния признаков на технологический процесс**.
